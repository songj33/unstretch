# 还原尺 unstretch

量出图片或视频里的“拉腿”特效拉了多少倍，再把它压回去。纯前端，文件只在浏览器里处理，不上传。

*A browser-only tool that measures and undoes vertical-stretch ("leg-lengthening") filters in images and videos. Nothing is uploaded.*

## 它做什么

常见的拉腿特效是一个按行重映射：分界线以上不动，分界线以下整条画面（连同背景）被纵向拉长 k 倍。所以只要知道两个数就能还原：**分界线在哪一行**、**拉了多少倍**。

还原尺用三类线索估计这两个数，并把依据列出来：

| 线索 | 怎么用 | 可靠程度 |
|---|---|---|
| 重复结构（砖缝、瓷砖、栏杆） | 比较分界线上下的周期；周期突变的那一行就是分界线 | 多条竖带一致时最可靠 |
| 已知形状（插座、球） | 本来是正方形或正圆的东西，量它现在的高÷宽 | 球体可靠；方块要正对镜头 |
| 人体比例 | 膝盖高÷身高的人群分布，反推倍数 | 只是统计，不是证据 |

只做能做的：几何拉伸可逆。磨皮、美白、AI 换脸把细节抹掉了，不在范围内。

## 怎么用

直接打开 `index.html`（单文件，无依赖），或者部署到任何静态站点。

1. 打开图片或视频。画中画、拼接的视频先用“只留一块画面”框出被处理的那一块。
2. 点“一键估计”。它会依次：识别人体、找分界线、找参照物。
3. 看“依据”列表。每条依据都写了它量到什么、算出多少倍。不放心就手动框参照物、量间距、拖人体点。
4. 导出 PNG，或者按原速录制还原后的视频（WebM）。

“一键估计”里的人体识别用 [MediaPipe Pose](https://github.com/google-ai-edge/mediapipe)，第一次使用时从 jsDelivr 加载（约 10 MB）。加载不了也不影响其它功能，人体比例可以手动点三个点。

## 实测结果

测试素材是 B 站上的几条“逆向美颜”视频。出于版权和肖像考虑，这些画面不在仓库里。

**有真值的一段**（视频里同时出现了拉伸版和未拉伸的原片，用特征点匹配得到真值：分界线第 518 行，1.63 倍）：

| 方法 | 分界线 | 倍数 |
|---|---|---|
| 一键估计（背景是砖墙） | 518 | 1.64 |
| 手动量两段砖缝 | 手动 | 1.64 |
| 人体比例，手动点三个点 | 手动 | 1.45（区间 1.26–1.65） |
| 人体比例，自动识别 | 518 | 1.46（区间 1.28–1.67） |
| 同一段里墙被人挡住的一帧，全自动 | 577 | 1.24（区间 1.11–1.39） |

**没有真值、只有视频作者手工还原结果的 7 段**（背景多是白墙，只能靠人体比例）：自动人体估计比作者的手工值平均低 0.16（−0.32 到 +0.01）。3 个未拉伸的对照画面给出 0.98–1.07。

**其它**：插座特写自动找到，1.17 倍；石球手动框圆，1.21 倍；自动找分界线在 18 个未拉伸的对照画面里误报 1 次。

## 自己造数据

拉腿是一个已知的简单变换，所以带标准答案的数据可以自己造，不需要去找别人的前后对比图。

```
python3 tools/make_dataset.py --src 你自己的照片文件夹 --procedural 100 --n 300 --out data/gen
node tools/evaluate.js data/gen
```

`make_dataset.py` 对每张图随机选分界线和倍数（约四分之一是不拉伸的对照），做行重映射，再模拟平台处理（缩小、JPEG 压缩），把真值写进 `labels.json`。`--procedural` 会程序化画出砖墙、瓷砖墙、白墙场景，没有照片也能跑。`evaluate.js` 用同一份算法打分，分两种情况：**全自动**（什么都不给）和**给定分界线**（相当于人已经把线拖准）。`data/` 不进仓库，只放你有权使用的图片。

当前版本的成绩（`--procedural 240 --n 240 --seed 1`，以及 13 张 scikit-image 自带样例照片生成的 150 张）：

| 数据 | 张数 | 全自动：作答 / 答对 / 答错 | 给定分界线：作答 / 答对 / 答错 |
|---|---|---|---|
| 程序化砖墙，拉伸 | 77 | 38 / 38 / 0 | 56 / 56 / 0 |
| 程序化瓷砖墙，拉伸 | 53 | 2 / 2 / 0 | 21 / 19 / 2 |
| 程序化白墙，拉伸 | 49 | 0 / 0 / 0 | 0 / 0 / 0 |
| 程序化场景，未拉伸对照 | 61 | 0 / 0 / 0 | 31 / 28 / 3 |
| 真实照片（含透视砖地、草地、碎石），拉伸与对照 | 150 | 0 / 0 / 0 | 0 / 0 / 0 |

“答对”指倍数误差在 5% 以内（全自动还要求分界线误差在 12 像素以内）。答对的样本里，分界线误差中位数 1 像素，倍数误差中位数 0.1%。

读法：背景线索宁可不答也不乱答。全自动只在周期结构清楚时作答（砖墙约一半），白墙和普通照片一律沉默，这时要靠人体比例或手动参照物。

这套数据已经抓出过三个真问题，都修了：

- 平滑区域上的 JPEG 块网格（8/16 像素）被当成“拉伸后的砖缝”。
- 砖块太大、周期超出扫描范围时，会锁到半周期上，算出错误倍数。
- **透视会冒充拉伸**：俯拍的砖地，周期本来就从上到下渐变。现在把每个窗口分成两半检查，周期在窗口内部就在变的算透视，不作答。

**想测真实 App 的特效**：自己架三脚架拍一段带砖墙或瓷砖背景的视频，用剪映、美图等的长腿功能处理一遍，原片和处理后的片子就是真正的一对。这能回答两个现在只靠推断的问题：真实特效是不是整行拉伸，分界线会不会跟着人动。

## 已知局限

- **自动人体估计偏保守。** 姿态模型见惯了正常比例，会把被拉长的小腿“认短”（脚踝、脚尖的点偏高），所以自动结果系统性偏小。把脚底点拖准后会接近手动结果。
- **人体比例的区间很宽**（约 ±15%），仰拍、厚底鞋、天生腿长都会让它偏大。它只该在没有任何参照物时作为参考。
- **按胯部猜的分界线很粗。** 背景里没有重复结构时，分界线只是放在模型认为的胯部，需要手动拖准。
- **形状自动候选很弱。** 只对边界清楚、正对镜头的矩形有效；有明暗的球、被遮挡的物体要手动框。
- **“分界线跟随人体”是实验功能**，机制测过，但没有在真正的跟踪式特效上验证过。
- **周期恰好是 8、16、32 像素的纹理会被忽略**，因为分不清它和视频压缩的块网格。
- **有透视的背景（地砖、斜拍的墙）不作答**，即使它确实被拉伸过。
- 只在桌面 Chrome 上测过。

## 开发

```
src/core.js        算法，纯函数，不依赖 DOM（浏览器和 Node 都能跑）
src/app.js         界面
src/style.css
src/template.html
build.py           把 src/ 拼成单文件 index.html
tests/             合成图上的测试（答案已知）
tools/             造数据、评测、从 ANSUR II 算人体比例分布的脚本
```

```
python3 build.py     # 生成 index.html
npm test             # node tests/synthetic.test.js
```

想自带姿态模型（离线使用）：把 `@mediapipe/pose@0.5.1675469404` 包里的文件放到 `vendor/pose/`，页面会优先从那里加载。

## 路线图

- 姿态模型换成对异常比例不敏感的做法（例如用人体分割轮廓直接量头顶、膝盖、脚底）
- 横向挤压（瘦身）用同一个模型按列处理
- 分段拉伸（只拉大腿到脚踝，脚不拉）的自动识别
- 迁移到 MediaPipe Tasks 的 PoseLandmarker

## 使用提醒

还原尺输出的是**估计值**，不是原片。导出时请连同依据一起说明，不要把它当作某个具体的人“本来的样子”，也不要用它去针对个人。
