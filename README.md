# 还原尺 unstretch

有些视频和照片里的大长腿是“拉”出来的：软件把画面的下半截整条拉长，腿就跟着变长了。还原尺帮你量出拉了多少，再把画面压回去。

它是一个网页，打开就能用。你的文件只在自己电脑的浏览器里处理，不会上传到任何地方。

*A web page that measures and undoes "leg-lengthening" filters in photos and videos. Everything runs in your browser; nothing is uploaded.*

## 它是怎么看出来的

拉腿的时候，被拉长的不只是腿，同一高度上的背景也一起被拉长了。所以背景会露馅：

- **砖墙、瓷砖**：下半截的砖比上半截的高。上下一比，就知道拉了多少倍，也知道是从哪一行开始拉的。这是最准的办法。
- **插座、球**：插座本来是正方形，球本来是圆的。如果变成了长方形、椭圆，量一下就知道拉了多少。
- **人的身材**：一般人膝盖离地的高度大约是身高的 28%。腿被拉长后这个比例会变大。但每个人身材不一样，这个办法只能给个大概。

有两种情况要另外处理：

- **拉伸是慢慢加大的**：有些滤镜不是从某一行起“一刀切”，而是从腰附近开始一点点加大，这样更不容易看出来。这时砖缝的间距不会突然变大，而是一路慢慢变大。工具会沿着砖缝一路量下去，看间距从哪一行开始变、到哪一行不再变。
- **镜头是仰着拍或俯着拍的**：这也会让下面的砖比上面的大，但这不是滤镜。区别在于：仰拍时间距从画面顶到底一直在变，而且门框、墙角这些竖直的边会向一头收拢。工具先把这部分扣掉，剩下的才算拉伸。

还有一种常见的处理是把整个画面横向压窄，让人显瘦。这种情况画面里所有东西都一起变窄了，只能靠本来是方的或圆的东西来量。

## 怎么用

1. 用浏览器打开 `index.html`。
2. 点“打开图片或视频”。如果是画中画或者拼在一起的视频，先用“只留一块画面”把要看的那一块框出来。
3. 点“一键估计”。它会自己找分界线、找背景里的参照物、看人的身材。
4. 看右边的“依据”。每一条都写着它量了什么、算出多少倍。觉得哪条可信，就点那条的“采用”。
5. 不放心可以自己动手：拖红色的分界线，框一个方形或圆，量两段砖缝的间距。如果拉伸是慢慢加大的，在“渐变段”里填上从开始拉到拉满一共多少行。
6. 满意了就导出图片，或者录一段还原后的视频。

第一次点“一键估计”时会联网下载一个识别人体的模型（约 10 MB）。下载不了也没关系，其它功能照常用。

## 准不准

**背景里有砖墙这类东西时，很准。** 有一段视频，博主正好也放了没拉过的原片，可以对答案：实际是从第 518 行开始拉长了 1.63 倍，工具量出来是第 518 行、1.64 倍。

**自己造了几百张测试图来考它。** 砖墙和瓷砖背景的图，它敢回答的 39 张全答对了；白墙和普通照片它一张都不回答，没有乱报。如果你先帮它把分界线拖准，它回答得更多，108 次里错了 5 次。

**慢慢加大的拉伸：敢回答的不多，回答了的大多是对的。** 造了 54 张这样的图，其中 38 张背景有砖或瓷砖。它回答了 7 张，对了 5 张；另外 2 张被当成了“一刀切”，倍数读低了。

**仰拍、俯拍：不会被当成滤镜，但会让它更不敢回答。** 56 张只是镜头倾斜、没有拉伸的图，它一张都没有误报。镜头倾斜又同时有拉伸的 64 张，它只回答了 7 张，对了 4 张。

**一张真实照片上的例子。** 一张网上的照片，旧版本读成“从某一行起拉长 1.09 倍”。新版本读成“从第 849 行起慢慢拉长，到第 1523 行拉满，约 1.19 倍（1.10–1.28）”。没有原片可以对答案；能说的只是画面左边的砖墙和右边的卷帘门分开量，得到的数差不多（1.18 和 1.21），而且门框是平行的，不像是仰拍造成的。

**只有白墙的时候，靠身材估的数不可靠。** 在有原片的那段视频上，它估的是 1.65–1.69，和实际的 1.63 很接近。但在另外 29 张截图上，和一位博主手工还原的结果经常对不上，有 10 张差了 0.4 以上。所以靠身材估出来的数只列出来给你参考，工具不会自己采用它。

**横向压窄。** 在一张自己造的图上（实际纵向拉长 1.40 倍、横向压到 90%），量出来是 1.40 倍和 89.4%。

具体的数字和测试方法在 [docs/details.md](docs/details.md)。

## 它做不到的

- **磨皮、美白、AI 换脸**：细节已经被抹掉了，没法还原。
- **局部的瘦脸、瘦腰**：那是把画面的一小块捏变形，不是整条拉长，这个工具管不了。
- **坐着、跪着、只拍到腿**：靠身材估需要人站直、全身都在画面里。
- **拉伸还没拉满，背景就没了**：比如砖墙只到腰，再往下是地面。这时只能说“至少拉了多少”，实际可能更多。工具会注明这只是下限，不会自己采用。
- **镜头倾斜，画面里又没有门框、墙角这类竖直的边**：倾斜了多少只能靠猜，倍数可能差一成左右。工具会注明，不会自己采用。
- **墙和地面的交界**：偶尔会被当成拉伸开始的位置。
- **俯拍的地砖**：地砖本来就近大远小，分不清是透视还是被拉过，所以它不回答。
- **白墙前面又没有任何参照物**：量不出来，它会直接告诉你量不出来。
- 只在电脑上的 Chrome 浏览器里测过。

## 一句提醒

还原尺给的是**估计**，不是原片。导出的时候请把依据一起说清楚，不要把结果说成某个人“本来的样子”，也不要拿它去针对具体的人。

## 给想改代码的人

```
src/core.js        算法（不依赖网页，浏览器和 Node 都能跑）
src/app.js         界面
src/style.css
src/template.html
build.py           把 src/ 拼成一个 index.html
tests/             用自己画的图做的测试，答案是已知的
tools/             造测试图、给算法打分的脚本
docs/details.md    测试记录和技术细节
```

```
python3 build.py     # 生成 index.html
npm test             # 跑测试
```

想自己造测试图、给算法打分：

```
python3 tools/make_dataset.py --src 你自己的照片文件夹 --procedural 100 --n 300 --out data/gen
node tools/evaluate.js data/gen
```

- 自动估计横向压窄了多少
- 只拉大腿到脚踝、脚不拉的情况
