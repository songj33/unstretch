# 测试记录和技术细节

这里是给想看具体数字的人准备的。日常使用看 [README](../README.md) 就够了。

几个词的意思：

- **倍数**：下半截被拉长到原来的多少倍。1.5 就是拉长了一半。
- **分界线**：从画面的哪一行开始往下被拉长。
- **真值**：确切知道的正确答案（比如手里有没处理过的原片）。
- **对照**：没被拉伸过的画面，用来检查工具会不会乱报。
- **ANSUR II**：2012 年美军公开的体测数据（4,082 名男性、1,986 名女性），人体比例的数字从这里算出来。

## 实测结果

测试素材是 B 站上的几条“逆向美颜”视频。出于版权和肖像考虑，这些画面不在仓库里。

**有真值的一段**（视频里同时出现了拉伸版和未拉伸的原片，用特征点匹配得到真值：分界线第 518 行，1.63 倍）：

| 方法 | 分界线 | 倍数 |
|---|---|---|
| 一键估计（背景是砖墙） | 518 | 1.64 |
| 手动量两段砖缝 | 手动 | 1.64 |
| 人体比例，手动点三个点 | 手动 | 1.45（区间 1.26–1.65） |
| 人体比例，自动识别 | 518 | 1.46（区间 1.28–1.67） |
| 同一段里墙被人挡住的一帧，全自动 | 577 | 1.24（区间 1.11–1.39） |

**自动人体比例：修掉了一个系统偏差，但单帧读数仍然只能当参考。** 姿态模型见惯了正常比例，会把被拉长的腿“认短”，直接读只能看到拉伸的一部分。现在的做法是按当前估计把画面还原、重新识别、再还原，反复到读数稳定。

在有真值的片段上（真值 1.63）：

| 画面 | 直接读 | 反复还原后 | 真值 |
|---|---|---|---|
| 站立的一帧 | 1.29 | 1.69 | 1.63 |
| 跳舞的一帧 | 1.46 | 1.65 | 1.63 |
| 这段的原片 | 0.98 | 1.00 | 1.00 |
| 另一个视频里的原片 | 0.99 | 0.99 | 1.00 |
| 整段视频，7 帧取中位（4 帧有读数，各帧 0.87–1.68） | – | 1.55 | 1.63 |

但在同一位博主 22 个视频的 29 个单帧上，对照他手工还原的倍数（不是真值；有原片可核对的两段里，一段他和原片一致，另一段偏低约一成）：

| | 相关系数 | 差的绝对值中位 | 相差超过 0.4 |
|---|---|---|---|
| 直接读 | 0.12 | 0.15 | 4 / 29 |
| 反复还原后 | 0.18 | 0.24 | 10 / 29 |

博主还原后的 13 个画面（应接近 1），反复还原后读数中位 1.10，范围 0.72–1.50。按“是否站直”筛选帧也没有改善。

读法：反复还原修掉了系统性的低估，在姿势端正的画面上很准；但单帧上姿态点一旦放错，读数会偏得更远。所以“一键估计”只把人体读数列为参考，不自动采用；视频会读多帧取中位。

**横向挤压。** 博主的 32 组可用对比里，有 10 组除了压回纵向，还把整幅画面横向拉宽了 4%–16%，而且横向比例从上到下是一致的，说明原片是整幅被压窄（瘦身）。工具里对应“横向倍数”。整幅都被压了，画面内部没有参照，只能靠本来是方或圆的东西来量：合成图上（真值纵向 1.40、横向 0.90）量出 1.40 和 0.894。

**其它**：插座特写自动找到，1.17 倍；石球手动框圆，1.21 倍；自动找分界线在 18 个未拉伸的对照画面里误报 1 次。

## 自己造数据

拉腿是一个已知的简单变换，所以带标准答案的数据可以自己造，不需要去找别人的前后对比图。

```
python3 tools/make_dataset.py --src 你自己的照片文件夹 --procedural 100 --n 300 --out data/gen
node tools/evaluate.js data/gen
```

`make_dataset.py`（加 `--hsqueeze 0.3` 可以让一部分样本同时被横向压窄）对每张图随机选分界线和倍数（约四分之一是不拉伸的对照），做行重映射，再模拟平台处理（缩小、JPEG 压缩），把真值写进 `labels.json`。`--procedural` 会程序化画出砖墙、瓷砖墙、白墙场景，没有照片也能跑。`evaluate.js` 用同一份算法打分，分两种情况：**全自动**（什么都不给）和**给定分界线**（相当于人已经把线拖准）。`data/` 不进仓库，只放你有权使用的图片。

当前版本的成绩（`--procedural 240 --n 240 --seed 1`，以及 13 张 scikit-image 自带样例照片生成的 150 张）：

| 数据 | 张数 | 全自动：作答 / 答对 / 答错 | 给定分界线：作答 / 答对 / 答错 |
|---|---|---|---|
| 程序化砖墙，拉伸 | 77 | 38 / 38 / 0 | 56 / 56 / 0 |
| 程序化瓷砖墙，拉伸 | 53 | 2 / 2 / 0 | 21 / 19 / 2 |
| 程序化白墙，拉伸 | 49 | 0 / 0 / 0 | 0 / 0 / 0 |
| 程序化场景，未拉伸对照 | 61 | 0 / 0 / 0 | 31 / 28 / 3 |
| 真实照片（含透视砖地、草地、碎石），拉伸与对照 | 150 | 0 / 0 / 0 | 0 / 0 / 0 |

“答对”指倍数误差在 5% 以内（全自动还要求分界线误差在 12 像素以内）。答对的样本里，分界线误差中位数 1 像素，倍数误差中位数 0.1%。

读法：背景线索宁可不答也不乱答。全自动只在周期结构清楚时作答（砖墙约一半），白墙和普通照片一律沉默，这时要靠人体比例或手动参照物。

这套数据已经抓出过三个真问题，都修了：

- 平滑区域上的 JPEG 块网格（8/16 像素）被当成“拉伸后的砖缝”。
- 砖块太大、周期超出扫描范围时，会锁到半周期上，算出错误倍数。
- **透视会冒充拉伸**：俯拍的砖地，周期本来就从上到下渐变。现在把每个窗口分成两半检查，周期在窗口内部就在变的算透视，不作答。

**想测真实 App 的特效**：自己架三脚架拍一段带砖墙或瓷砖背景的视频，用剪映、美图等的长腿功能处理一遍，原片和处理后的片子就是真正的一对。这能回答两个现在只靠推断的问题：真实特效是不是整行拉伸，分界线会不会跟着人动。

## 已知局限

- **自动人体读数只是参考。** 单帧读数很散（见上表），个人身材、姿势和拍摄角度都会带偏它。把三个点拖到真实位置、或者用视频多帧，会好一些。
- **横向只支持整幅缩放，而且没有自动估计。** 局部的瘦腰、瘦脸（液化）还原不了；横向倍数要靠方或圆的参照物，或者手动调。
- **圆的测量对框得准不准很敏感。** 手动框圆时让椭圆尽量贴住轮廓，框大两成就会量错。
- **人体比例的区间很宽**（约 ±15%），仰拍、厚底鞋、天生腿长都会让它偏大。它只该在没有任何参照物时作为参考。
- **按胯部猜的分界线很粗。** 背景里没有重复结构时，分界线只是放在模型认为的胯部，需要手动拖准。
- **形状自动候选很弱。** 只对边界清楚、正对镜头的矩形有效；有明暗的球、被遮挡的物体要手动框。
- **“分界线跟随人体”是实验功能**，机制测过，但没有在真正的跟踪式特效上验证过。
- **周期恰好是 8、16、32 像素的纹理会被忽略**，因为分不清它和视频压缩的块网格。
- **有透视的背景（地砖、斜拍的墙）不作答**，即使它确实被拉伸过。
- **坐着、跪着、只拍到腿的画面量不了。** 试过用两段肢体的长度比来量，正面坐姿时大腿朝镜头伸过来会显短，和小腿被拉长分不开，效果不好，没有保留。
- 只在桌面 Chrome 上测过。
